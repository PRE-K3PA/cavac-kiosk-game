# Clean Code 규칙

`AGENTS.md` 가 이 파일보다 우선합니다. `TEAM_OWNERSHIP.md` 는 작업 소유권 경계를 정의합니다.

## 기존 패턴 우선

컴포넌트, 훅, 유틸리티, 스토어, 타입, 검증 스키마를 새로 도입하기 전에
동일하거나 유사한 구현이 있는지 먼저 검색합니다.

재사용 > 확장 > 리팩터링 > 신규 생성

## 컴포넌트

하나의 컴포넌트는 하나의 명확한 책임을 가집니다.

다음 구조를 피합니다.

- 지나치게 큰 화면 컴포넌트
- UI, 저장 로직, 게임 로직이 한 파일에 함께 있는 구조
- 의미 없는 래퍼 컴포넌트
- 코드 줄 수를 줄이려고만 만든 컴포넌트
- 기존 공용 컴포넌트와 중복되는 기능별 로컬 컴포넌트

다음 경우에 컴포넌트로 분리합니다.

- 여러 곳에서 재사용되는 경우
- 독립적인 동작을 가지는 경우
- 의미 있는 UI 개념을 나타내는 경우
- 가독성을 크게 높이는 경우

## 함수

작고 이름이 명확한 함수를 우선합니다. 가독성이 좋아지면 early return 을 씁니다.

다음을 피합니다.

- 서로 관련 없는 동작을 제어하는 boolean 플래그
- 깊게 중첩된 조건문
- 불필요하게 범용적인 헬퍼 함수
- `processData`, `handleData`, `temp`, `value` 처럼 의미가 모호한 이름

## React

`useEffect`, `useMemo`, `useCallback`, 파생 상태, 중복 상태를 불필요하게 쓰지 않습니다.
명확한 이유 없이 props 나 store 의 값을 local state 로 복제하지 않습니다.

## 타입

`any`, 중복된 interface, 지나치게 범용적인 타입, TypeScript 오류를 없애기만 하려는 타입 캐스팅을
피합니다. 사용 가능한 도메인 타입이 있으면 재사용합니다.

## 담당 영역

Clean Code 개선을 이유로 다른 담당자의 관련 없는 파일을 수정하지 않습니다.
코드 정리를 이유로 작업 범위를 넓히지 않습니다.

## 주석

코드만 봐도 알 수 있는 내용은 주석으로 쓰지 않습니다. 구조와 네이밍으로 이해되게 만듭니다.
주석은 코드로 드러나지 않는 도메인 제약, 우회 처리의 이유, 외부 동작에만 씁니다.
